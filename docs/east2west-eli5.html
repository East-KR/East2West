East2West 한눈에

옛 가게와 새 가게,
맛이 똑같을까?

East2West는 옛 프로그램(as-is)과 새 프로그램(to-be)이 버그까지 똑같이 움직이는지 확인해요.

순서는 이래요

왼쪽부터 차례대로

  1. 1사진 찍기옛 가게 맛 기록
  2. 2도장 찍기도구가 자동으로
  3. 3시식가 시험일부러 맛 바꾸기
  4. 4새 가게 맛보기같은지 비교
  5. 5성적표믿을 수 있나
  6. 6고치고 다시뭐가 달라졌나
에이전트(Claude)가 해요 도장(승인)은 도구가 자동으로

하나씩 보면

1 · 골든 기록

옛 가게 맛을 사진으로 남겨요

옛 프로그램을 한 단계씩 눌러 보며 화면을 전부 찍어 둬요. 이 사진첩이 정답지예요. 버그가 있어도 그게 정답이에요.

에이전트가 해요

실제로는 테스트를 as-is에서 돌리며 --record golden/<app>. 화면 내용, 값, 알림창, 스크린샷이 저장되고, 통합 화면의 시나리오 탭에서 단계마다 볼 수 있어요.

2 · 자동 승인

기록이 끝나면 도장이 찍혀요

정답지를 새로 쓰면 도구가 도장을 찍어요. 비교할 때마다 어느 도장의 정답지로 했는지 남겨서, 나중에 섞이지 않아요.

도구가 알아서 해요

실제로는 기록이 끝날 때와 비교·결함 주입을 시작할 때 정답지(golden/<app>)가 바뀌었으면 oracle.auto_approve가 승인자 '자동 승인'으로 도장을 찍어요. 에이전트가 정답지나 도장을 손으로 고치는 건 hook이 막아요.

3 · 결함 주입

시식가가 진짜 맛을 아는지 시험해요

옛 가게 맛을 일부러 살짝 바꿔 놓고, 테스트가 "어? 달라!" 하고 알아채는지 봐요. 못 알아채는 테스트는 믿을 수 없어요.

에이전트가 해요

실제로는 east2west mutate e2e/<app> --compare golden/<app>. 숫자, 반올림, 조건, 알림창, 문구, 500 오류를 하나씩 넣어 봐요. 놓친 결함이 테스트 빈틈을 알려줘요.

4 · to-be 비교

새 가게 맛을 정답지와 비교해요

같은 순서로 새 프로그램을 눌러 보며 한 단계씩 사진과 맞춰 봐요. 값이나 알림이 다르면 "여기 달라요" 하고 알려줘요.

에이전트가 해요

실제로는 pytest e2e/<app> --base-url <to-be> --compare golden/<app>. 화면 구조(frameset, table, 드롭다운 종류)가 달라도 내용이 같으면 통과해요.

5 · 검증 보고서

믿어도 되는지 성적표를 줘요

"다른 곳이 몇 개"와 함께 "이 결과를 믿어도 되나"를 보여줘요. 하나라도 빠지면 신뢰 불가가 떠요.

자동으로 만들어져요

실제로는 east2west report …. 에이전트의 말이 아니라 실행 기록 파일만 읽고 만들어요. 사람은 east2west ui의 실행 탭에서 같은 판정을 "무엇이 · as-is · to-be" 표와 캡처로 봐요.

6 · 고치고 다시

기록장을 보고 고친 뒤 다시 맛봐요

맛볼 때마다 기록장에 남아요. 새 가게를 고치고 다시 맛보면 "지난번보다 뭐가 좋아졌고 뭐가 나빠졌나"만 알려줘요.

자동으로 쌓여요

실제로는 비교할 때마다 runs/<app>/에 결과가 남고, east2west status가 남은 실패와 지난 실행 대비 변화(통과로 바뀜 / 새로 실패)를 보여줘요. east2west ui의 시나리오·실행 탭은 시나리오별 이력을 한 화면에 모아요.

도와주는 도구 두 개

필요할 때만 써요

스모크 · Jev 러너

메뉴를 한 입씩 다 맛봐요

화면이 수백 개면 하나하나 테스트를 못 짜요. "조회 버튼 누르기" 한 문장으로 모든 화면을 훑어서, 안 열리거나 오류 나는 화면을 찾아요.

에이전트가 해요

실제로는 east2west run screen_smoke.yaml. 처음 한 번만 Jev가 화면마다 버튼을 고르고, 다음부터는 기억(캐시)으로 공짜로 돌아요. 데모에서 결함 5개 전부 잡음.

탐색기 · crawl

가게 구석구석을 돌아다니며 지도를 그려요

버튼을 모두 눌러 보고 "어디서 어디로 갈 수 있는지" 지도를 만들어요. 그 지도로 테스트 초안도 자동으로 써 줘요. 삭제나 결제 같은 위험한 버튼은 안 눌러요.

에이전트가 해요

실제로는 east2west crawl <시작 주소> --dry-run으로 누를 버튼을 먼저 보고 실행해요. AI 없이 돌아서 비용이 0이에요. 저장 버튼은 진짜로 누르니 테스트 서버에서만.

한 줄로 줄이면

옛 프로그램을 사진 찍으면 도구가 도장을 찍고, 시식가 실력을 시험한 뒤, 새 프로그램이 사진과 같은지 맞춰 보고, 믿을 수 있는 성적표를 줘요. 고치고 다시 맞춰 보면 뭐가 달라졌는지만 알려줘요.
